# Medium Article Semantic Search (Airflow + Pinecone)

An Apache Airflow pipeline that downloads a dataset of Medium articles, turns each article title into a 384-dimensional sentence embedding, loads the embeddings into a Pinecone serverless vector index, and runs a sample semantic query to confirm the index works. Airflow runs locally in Docker via Docker Compose.

The pipeline is a full rebuild on every run: it deletes and recreates the index, then re-embeds and re-upserts the entire dataset.

This is a course project (DATA 226, HW11).

## What the pipeline does

```
download_data ──> preprocess_data ──┐
                                    ├──> generate_embeddings_and_upsert ──> test_search_query
create_pinecone_index ──────────────┘
```

1. **download_data** downloads `medium_data.csv` from a public S3 bucket into `/tmp/medium_data/`. It fails if the HTTP status is not 200.
2. **preprocess_data** loads the CSV, fills in `title` and `subtitle`, builds a metadata dictionary `{'title': "<title> <subtitle>"}` for each row, assigns each row an ID (its row position as a string, `"0"` through `"N-1"`), and writes `/tmp/medium_data/medium_preprocessed.csv`.
3. **create_pinecone_index** reads the API key from the Airflow Variable `pinecone_api_key`. If an index named `semantic-search-fast` already exists, it deletes it. It then creates a new serverless index (AWS, `us-east-1`, 384 dimensions, `dotproduct` metric) and waits until the index reports ready.
4. **generate_embeddings_and_upsert** loads the `all-MiniLM-L6-v2` sentence-transformer on CPU. It encodes titles in batches of 100 and upserts `{id, values, metadata}` records into the index.
5. **test_search_query** embeds the sample query `"what is ethics in AI"`, retrieves the top 5 matches with metadata, and prints them to the task log.

`download_data` and `preprocess_data` run in parallel with `create_pinecone_index`. `generate_embeddings_and_upsert` waits for both, and `test_search_query` runs last.

## Architecture

`docker-compose.yaml` defines the following services. All of them use the `apache/airflow:2.10.5` image except PostgreSQL.

| Service | Image | Role |
|---------|-------|------|
| `postgres` | `postgres:16` | Airflow metadata database. Credentials are `airflow` / `airflow`. Data is kept in the named volume `postgres-db-volume`. |
| `airflow-init` | `apache/airflow:2.10.5` | Runs once. Creates the `/sources` folders, runs `airflow db migrate`, and creates the web UI user. |
| `airflow-webserver` | `apache/airflow:2.10.5` | Web UI. Published at **http://localhost:8090** (container port 8080). |
| `airflow-scheduler` | `apache/airflow:2.10.5` | Schedules and runs tasks with the `LocalExecutor`. |

Shared settings:

- **Executor:** `LocalExecutor`. Tasks run as subprocesses of the scheduler container. No Celery or Redis is required.
- **Example DAGs:** disabled (`AIRFLOW__CORE__LOAD_EXAMPLES: 'false'`).
- **New DAGs start paused** (`DAGS_ARE_PAUSED_AT_CREATION: 'true'`), so you must unpause `Medium_to_Pinecone` before it runs on its schedule.
- **Python packages:** `sentence-transformers`, `pinecone`, and `numpy<2` are installed through `_PIP_ADDITIONAL_REQUIREMENTS` each time a container starts. The versions are not pinned, and the install adds startup time.
- **Pinecone key:** `AIRFLOW_VAR_PINECONE_API_KEY` is set from the `PINECONE_API_KEY` variable in a `.env` file next to the compose file. Airflow exposes `AIRFLOW_VAR_<NAME>` environment variables as `Variable.get("<name>")`.
- **Bind mounts:** `./dags`, `./logs`, and `./plugins` are mounted into `/opt/airflow/`.

## The DAG in detail

| Setting | Value |
|---------|-------|
| `dag_id` | `Medium_to_Pinecone` |
| Description | Build a Medium Posting Search Engine using Pinecone |
| Schedule | Every 7 days (`timedelta(days=7)`) |
| Start date | 2026-11-01 |
| Catchup | Disabled |
| Retries | 1, with a 5-minute delay |
| Tags | `medium`, `pinecone`, `search-engine` |

### Tasks

| Task | Inputs | Output | Notes |
|------|--------|--------|-------|
| `download_data` | None (hard-coded URL) | Path to the raw CSV (`/tmp/medium_data/medium_data.csv`) | Source: `https://s3-geospatial.s3.us-west-2.amazonaws.com/medium_data.csv`. The file has 2,499 lines including the header, so 2,498 records. |
| `preprocess_data` | Raw CSV path | Path to the preprocessed CSV (`/tmp/medium_data/medium_preprocessed.csv`) | Expects `title` and `subtitle` columns. Adds `metadata` and `id` columns. |
| `create_pinecone_index` | Airflow Variable `pinecone_api_key` | Index name (`semantic-search-fast`) | Deletes the existing index if present, creates a new one, and polls `describe_index` until it is ready. |
| `generate_embeddings_and_upsert` | Preprocessed CSV path, index name | Index name | Encodes titles in batches of 100 and upserts with `index.upsert(vectors=...)`. |
| `test_search_query` | Index name | None (results go to the log) | Queries with `"what is ethics in AI"`, `top_k=5`, `include_metadata=True`. |

### Task dependencies

```python
data_path            = download_data()
preprocessed_path    = preprocess_data(data_path)
index_name           = create_pinecone_index()
final_index_name     = generate_embeddings_and_upsert(preprocessed_path, index_name)
test_search_query(final_index_name)
```

## Pinecone index and embedding model

| Property | Value |
|----------|-------|
| Index name | `semantic-search-fast` |
| Type | Serverless |
| Cloud and region | AWS, `us-east-1` |
| Dimension | 384 |
| Metric | `dotproduct` |
| Record ID | Row position in the preprocessed CSV, as a string |
| Stored metadata | `{"title": "<title> <subtitle>"}` |
| Namespace | Default (`''`) |

The embedding model is `all-MiniLM-L6-v2` from sentence-transformers, which outputs 384-dimensional vectors. The DAG runs it on CPU. Only the title and subtitle text are embedded; article bodies are not used.

## Prerequisites

- **Docker** and **Docker Compose v2** (`docker compose version`). The stack needs several GB of disk space and memory. The first start downloads the Airflow and PostgreSQL images and installs Python packages.
- **A Pinecone account and API key** from [app.pinecone.io](https://app.pinecone.io). The index is serverless on AWS, so your account must allow it in `us-east-1`.
- **Network access** to `s3-geospatial.s3.us-west-2.amazonaws.com`, `api.pinecone.io`, and `huggingface.co`. The embedding model is downloaded from Hugging Face on first use.
- **Free ports:** `8090` (Airflow UI).

## Setup and running

### 1. Create the `.env` file

Create a file named `.env` next to `docker-compose.yaml`. Docker Compose reads it automatically:

```bash
echo "PINECONE_API_KEY=<your-pinecone-api-key>" > .env
```

Do not commit this file. The repo does not include a `.gitignore` yet (see [Suggested cleanup](#suggested-cleanup)).

### 2. Start the stack

```bash
docker compose up -d
```

`airflow-init` runs first. It migrates the database and creates the web UI user. The webserver and scheduler start after it finishes. Check progress with:

```bash
docker compose ps
docker compose logs -f airflow-init
```

### 3. Log in to the web UI

Open **http://localhost:8090** and sign in with:

- **Username:** `airflow`
- **Password:** `airflow`

These are local development defaults set in `airflow-init`. Change them before you expose the port anywhere else.

### 4. Confirm the Pinecone key (optional)

The compose file sets `AIRFLOW_VAR_PINECONE_API_KEY` from `.env`, and Airflow reads that environment variable when the DAG calls `Variable.get("pinecone_api_key")`. You can also add the variable in the UI under **Admin > Variables** with the key `pinecone_api_key`, as shown in `screenshots.pdf` (page 1).

### 5. Unpause and trigger the DAG

Either use the UI (toggle **Medium_to_Pinecone** on, then click the play button), or run:

```bash
docker compose exec airflow-scheduler airflow dags unpause Medium_to_Pinecone
docker compose exec airflow-scheduler airflow dags trigger Medium_to_Pinecone
```

Once unpaused, the scheduler runs the DAG every 7 days from its start date. `catchup` is disabled, so it does not backfill missed intervals.

### 6. Stop or reset

```bash
docker compose down          # stop containers, keep the Airflow metadata database
docker compose down -v       # also delete the PostgreSQL volume (full reset)
```

Stopping the stack does not delete the Pinecone index. Only the next DAG run replaces it.

## Querying the index outside Airflow

The index is ready to query after a successful run. Use the same model and dimensions as the DAG:

```python
import os
from sentence_transformers import SentenceTransformer
from pinecone import Pinecone

model = SentenceTransformer("all-MiniLM-L6-v2")
index = Pinecone(api_key=os.environ["PINECONE_API_KEY"]).Index("semantic-search-fast")

query_vector = model.encode("what is ethics in AI").tolist()
results = index.query(vector=query_vector, top_k=5, include_metadata=True)

for match in results["matches"]:
    print(match["id"], round(match["score"], 4), match["metadata"]["title"][:80])
```

Use the same model for queries and for indexing. Vectors from different models are not comparable.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `Variable pinecone_api_key does not exist` | No key in the environment or the Variables table. | Confirm `.env` contains `PINECONE_API_KEY`, then run `docker compose up -d` again. Or add the variable in the UI. |
| `Index.upsert() is a keyword-only method` | The DAG calls `index.upsert(...)` with a positional argument. | Use `index.upsert(vectors=upsert_data)`, as in `dags/build_pinecone_search.py`. |
| `409 ALREADY_EXISTS` in `create_pinecone_index` | Two runs are creating the index at the same time. | Let the retry finish, or avoid triggering a manual run while a scheduled run is active. |
| `Failed to download data: HTTP Status ...` | The S3 object moved or the network is blocked. | Check the URL in a browser and the container's outbound network access. |
| The DAG does not appear in the UI | The DAG processor has not parsed the file yet, or the file has a syntax error. | Check the DAG processor log under `logs/dag_processor_manager/`, then wait about 30 seconds. |
| The DAG never runs on schedule | It is still paused (new DAGs start paused). | Unpause it with the toggle or `airflow dags unpause`. |
| Scheduler or webserver restarts repeatedly | Package installation at startup failed, or PostgreSQL is not healthy yet. | Run `docker compose logs airflow-scheduler`. |
| Web UI shows a blank or unhealthy state for a while | The first start installs `sentence-transformers` and waits for the webserver health check (`start_period: 120s`). | Wait a few minutes. |

## Known issues and limitations

These are things a reader should know. They are not all blocking.

1. **Root-level copy is out of date.** `build_pinecone_search.py` at the repo root still calls `index.upsert(upsert_data)`. That call fails with the error described above. Airflow does not load this file, but do not copy it into `dags/`.
2. **Full rebuild on every run.** `create_pinecone_index` deletes `semantic-search-fast` and creates it again. Each run re-embeds all 2,498 records. In the logged run, the embedding and upsert step took about 20 seconds on CPU, plus the one-time model download. There is no incremental update.
3. **Missing subtitles become the string `"nan"`.** The code calls `astype(str)` before `fillna('')`. `astype(str)` already converts `NaN` to `"nan"`, so `fillna` has no effect. Rows without a subtitle are embedded with `"nan"` appended to the title.
4. **`eval()` on CSV content.** The metadata column is written to CSV as the text of a Python dictionary, then read back and converted with `eval()`. Anything in that column runs as code. The dataset is public, but `ast.literal_eval()` is the safe choice here.
5. **Metadata holds only the title and subtitle.** Search results show the first 50 characters of the title. The article body, URL, and author are not stored.
6. **Record IDs depend on row position.** IDs are `0` through `N-1`. If the dataset changes order or gains rows, the IDs change. This is fine for a full rebuild but breaks any external reference to an ID.
7. **Duplicate articles.** The search output in `screenshots.pdf` shows IDs `1` and `1634` with the same title, so the dataset appears to contain duplicate articles.
8. **Intermediate files live in `/tmp`.** The DAG writes to `/tmp/medium_data/` inside the scheduler container. Files are lost when the container is recreated, and every run downloads the file again.
9. **Unpinned dependencies.** Only `numpy<2` is pinned. The packages are installed at container start, so a fresh container can pick up different versions.
10. **Deprecated and stray code.** The DAG uses `schedule_interval`, which Airflow 2.10 still accepts but treats as deprecated (`schedule` is the newer name). `print(preprocessed_path)` runs at parse time, so the DAG processor log gets a line with an unrendered Jinja template. The docstring sits after the `with DAG(...)` line, so it is not the DAG's documentation.
11. **No tests.** Nothing in the repo tests the DAG beyond the `test_search_query` task, which runs against the live index.

## Security notes

- **Local development only.** The compose file uses default passwords for PostgreSQL and the Airflow UI, and it publishes the UI on port 8090.
- **Unencrypted Variables.** `AIRFLOW__CORE__FERNET_KEY` is set to an empty string, so Airflow does not encrypt stored Variables and connections. The screenshot shows `pinecone_api_key` with "Is Encrypted: False". Set a Fernet key before storing real secrets in the metadata database.
- **API key handling.** The key lives in `.env` and in the container environment, and `docker compose config` prints it. Keep `.env` out of version control and rotate the key if it leaks.
- **Public data.** The dataset comes from a public, unauthenticated URL. The pipeline does not verify a checksum, so a changed file would be indexed without warning.

## Suggested cleanup

These changes would make the repo easier to maintain. None of them are required to run the pipeline.

- Delete the root-level `build_pinecone_search.py`, or replace it with a copy of `dags/build_pinecone_search.py`. The root copy is not used by Airflow.
- Add a `.gitignore` with at least `.env`, `logs/`, `__pycache__/`, and `*.pyc`. The repo currently tracks logs and bytecode.
- Replace `eval` with `ast.literal_eval`, and fix the `astype(str)` / `fillna` order.
- Remove `print(preprocessed_path)` from the DAG body, and move the docstring into `DAG(..., doc_md=...)`.
- Pin `sentence-transformers`, `pinecone`, and `numpy` versions in a `requirements.txt`, and mount it instead of using `_PIP_ADDITIONAL_REQUIREMENTS`.
- Keep the `dags/` copy as the single source of truth.
